# Contract audit: PR 9635, head d8a56d1a38ca

Read-only inspection of the supplied source and diff. No build or behavioral reproduction was done here. Scope is snapshot exclusion with the default `git.ignore-filters = ["lfs"]`; findings below are hypotheses or contract gaps unless stated as direct source observations.

## Implemented contract and coverage

- The default is present in `cli/src/config/misc.toml:29`, the schema at `cli/src/config-schema.json:569-583`, and the fallback in `lib/src/git.rs:125-130`. `TreeStateSettings::try_from_user_settings` collects the configured values at `lib/src/local_working_copy.rs:995-1015`; `TreeState::empty` activates them only for a Git backend at lines 1122-1127. An empty list disables filtering (`lib/src/gitattributes.rs:408-413`).
- Each snapshot constructs a fresh attribute evaluator against the current tree and disk (`lib/src/local_working_copy.rs:1379-1383`). It checks files during ordinary traversal (1745-1755), tracked files in Git-ignored directories (1818-1825), and missing tracked files during deletion emission (1910-1921). This avoids the straightforward accidental deletion of tracked LFS pointers. The PR has regression tests for each major route (`lib/tests/test_local_working_copy.rs:3251-3370`) and tests backend gating (`3195-3248`).
- The attribute evaluator uses disk-first with tree fallback (`lib/src/gitattributes.rs:229-283`), which is explicitly tested after checkout (`lib/tests/test_local_working_copy.rs:3251-3291`). The unit suite exercises patterns, overrides, macros, errors, and filter values (`lib/src/gitattributes.rs:550-939`). CLI tests exercise temporary snapshots for `diffedit` and `run` (`cli/tests/test_diffedit_command.rs:22-66`, `cli/tests/test_run_command.rs:71-115`).
- Documentation is explicit that this is snapshot-only and does not clean/smudge or hydrate LFS (`docs/config.md:2001-2017`, `docs/git-compatibility.md:38-43,77-83`). It also notes the `jj workspace` Git command limitation. That addresses prior review discussion about the workaround. Prior review also requested dropping `web/docs`, feature gating, and using `gix::attrs`; the supplied diff reflects those changes.

## High-value hypotheses and missing tests

1. **Changed `.gitattributes` can make a previously tracked ordinary file stop snapshotting immediately.** This follows directly from disk-first loading and the filter check preceding tracked-state processing (`gitattributes.rs:229-283`; `local_working_copy.rs:1745-1755`). It may be intended, but it changes what `jj status`/`jj diff` can show, and can hide edits to files that are not actually LFS pointers. Add a CLI test where an existing tracked text file is edited while a new `*.txt filter=lfs` rule is added, checking status and subsequent `git.ignore-filters=[]` recovery. Confirm this policy is desirable for malformed/misapplied attributes.
2. **No snapshot diagnostic identifies a file omitted specifically by this rule.** The filtering branches return or continue without an `UntrackedReason`, a count, or a warning (`local_working_copy.rs:1745-1755,1818-1825,1910-1921`). As a result, a newly created LFS path may be absent from both the tree and the untracked-file hints, and a modified tracked path can appear clean. Test end-user `jj status`, `jj file list`, and `jj diff` output for a fresh and tracked LFS path and assess whether documentation alone is sufficient. This is a usability/observability gap, not evidence of wrong tree content.
3. **Attribute source precedence and absence need an end-to-end matrix.** The evaluator falls back to the tree if the disk `.gitattributes` is absent (`gitattributes.rs:250-269`), so deleting a tracked `.gitattributes` file does not remove its filtering effect until after a snapshot changes the tree. Existing fallback test covers pointer preservation, but not whether the deleted attributes file is recorded as deleted and whether the *next* snapshot then accepts a previously excluded file. Add a two-snapshot test to pin that transition. Also test a nested disk `.gitattributes` overriding a stored root rule.
4. **Conflict selection may choose an arbitrary file side for attributes.** On an unresolved `.gitattributes` tree value, `TreeFileLoader::load` takes the first file side (`gitattributes.rs:111-126`), then uses it for filtering if disk attributes are missing. A conflict can therefore silently select one filter policy. Test conflicted `.gitattributes` with no disk file and distinct filter rules on sides; decide whether to reject, preserve current tree content, or document the fallback. This is a hypothesis about policy, not a demonstrated nondeterminism bug.
5. **Filesystem behavior deserves platform coverage.** `DiskFileLoader` checks `symlink_metadata`, then opens the path (`gitattributes.rs:151-183`); a replacement between those calls could change the object read, and case-sensitive `Case::Sensitive` is hardcoded (`gitattributes.rs:358-364`). Compare to Git's behavior on case-insensitive filesystems and test symlinked `.gitattributes`, unreadable files, and `NotADirectory` parent transitions. The unit tests cover synthetic loader errors and `NotADirectory`, but do not exercise all native filesystem conditions.
6. **Performance regression hypothesis for large LFS trees.** Every candidate file invokes attribute matching (`local_working_copy.rs:1745-1750`), and each attribute file is read wholly (`gitattributes.rs:273-295`). Cache loading holds an async mutex while reading and recursively obtaining parents (`gitattributes.rs:216-235`). The no-match list short-circuits in `filter_matches`, but default `["lfs"]` makes this new work universal for Git-backed snapshots. Benchmark a large Git-backed checkout with no `.gitattributes`, one root rule, and many nested rules versus base. Assess peak memory and parallel traversal throughput before treating performance as a blocker.

## API, build, and compatibility notes

- `TreeStateSettings` is public and receives a new required public field (`lib/src/local_working_copy.rs:977-993`). Downstream Rust users constructing it with a struct literal must update; this is a source compatibility change. The patch updates its in-tree literals in `run` and merge tools, but an ecosystem/semver note may be warranted if the type is treated as stable public API.
- The `gitattributes` module is feature-gated in `lib/src/lib.rs`; call sites are gated in `local_working_copy.rs` and CLI conversion (`cli/src/command_error.rs:38-39,747-753`). Confirm `jj-lib --no-default-features` and CLI feature configurations compile. Prior review explicitly identified this build risk; the current diff appears to address it, but source inspection is not compilation.
- `Cargo.lock` changes a broad dependency set beyond an attributes parser. No direct new `gix-attributes` dependency appears in the final manifest; prior review requested use of the gix re-export. Run locked builds on the repository MSRV and CI feature matrix to catch lockfile or feature resolution changes.
- `GitAttributesError` stores a generic message and source (`gitattributes.rs:429-435`). Several failures have no `.gitattributes` path in the message, especially tree reads and `read_to_end` (`gitattributes.rs:106-145,277-286`). CLI adds only “Failed to process .gitattributes.” (`cli/src/command_error.rs:747-753`). A missing path makes a multi-directory failure hard to locate. Test the rendered error on a deliberately unreadable nested attributes file and consider adding path context.
- Git attributes under `$GIT_DIR/info/attributes` and global attributes are not modeled (the in-source unit test explicitly notes the info file omission at `gitattributes.rs:630-634`). This is consistent with the documented partial compatibility claim, but worth making visible in the final report as a limit on parity with `git check-attr`.
